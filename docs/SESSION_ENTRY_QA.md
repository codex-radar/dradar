# #0057 固定入口的验收边界

本文件是候选的最小验证方案，不是运行真实模型或生产样本的授权。当前只有纯夹具证据，不能声称 Claude Code 已接受或原用户问题已解决。

## 已实现的控制边界

- 已实现的内层 `dradar-session` 检查固定 Git 来源和 commit，直接调用同版本 `run --follow`，不使用通用 OTA launcher。外层 A 方案已完成本地封装/安装链路，实际分发与生产发布仍未授权。Git-only 不作为默认交付。
- 本机通过内存返回值调用运行、进度和有限恢复步骤；外层不解析命令数组，也不解析自身 stdout。输出是脱敏人话进度。
- 新版本为0.5.192，区别于已发布0.5.190和保留的0.5.191候选。旧 JSON 接口与既有安全加固保留；旧复制文本不会自动变短，需重新复制。
- 同一份复制说明自动创建/复用本任务专用环境，写入固定依赖锁行，执行uv pip强制哈希安装，随后用该环境的Python -I启动bootstrap。没有另一个网页阶段，不把命令交给用户手敲；不能依赖全局同名命令或仅OTA更新产生新的console-script。
- release/bootstrap/dradar_bootstrap.py已保留可信bootstrap加载后的Git隔离单次重试和最小上报，并由bootstrap_receipt.py区分CLI已加载与业务暂停。安装/哈希失败发生在bootstrap加载前时，只能如实给出本地错误。

## 纯夹具证据

`test_run_session.py` 的固定入口集成测试经过实际 session_entry、CLI 参数解析、本地运行/进度步骤；只有 API、Fleet 和环境被替换为惰性夹具。它验证固定5并发进入正确计划、进度到终态、无外层命令解释、无真实题或 Docker 启动。其余测试覆盖补交上限、一次性重查、确认/取消、非TTY暂停后显式确认同范围恢复、确认编号的一次性消费/过期/作用域变化拒绝、未知状态和隐私输出。普通确认不强制手工终端；仅认证/秘密输入保留用户终端边界。

`test_session_entry.py` 验证来源/commit变化时在运行和上报前停止、不会跳转通用OTA启动器，以及启动故障报告只在专用头携带运行码、无敏感队列、无跨来源重定向。

Web 的 session-copy-entry 测试调用真实复制、再次复制、手动复制函数，使用惰性剪贴板/DOM；覆盖中英文与八类Harness的计划入口。它证明组件输出同一固定入口，不能证明某个模型会执行它。

## 已安装标准包的本地链路

`scripts/build_bootstrap.py` 确定性构建无第三方依赖的通用wheel；`scripts/qa_bootstrap_local.py --web-source <本地Web/index.html>`读取真实复制组件的安装配方和固定入口，在临时目录和仅loopback服务中执行。

真实执行：uv强制哈希安装、已安装bootstrap子进程、私有启动回执、流式短行输出、实际CLI解析与本地控制代码。夹具边界：内层uvx/Git解析、VCS安装元数据、API/Fleet、Docker/模型环境。测试启用内层UV离线约束，未运行真实Git部署或真实模型。

覆盖：错误哈希拒绝、正确哈希安装、已有同版本时错误哈希重装仍拒绝；隔离模块入口不受当前目录/PYTHONPATH影响；Git一次失败后重试成功、两次失败单次最小上报；非TTY确认后同范围续跑、取消、重复确认拒绝且不报启动失败；短行在进程结束前可见。带空格的本地路径也在macOS本机执行。

尚未验证：Linux/Windows原生进程、Windows临时目录ACL行为、全新机器Python下载、正式Pages资产的真实UV User-Agent边缘访问、实际Git网络/安装以及Claude实际接受。通用wheel不等于已完成这些原生验证。
